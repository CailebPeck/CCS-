# Coastline Hub

One mobile app for the Coastline group — built with [Capacitor](https://capacitorjs.com) so a single web codebase ships as a native iOS app (App Store) and Android app (Google Play).

**Inside the app:**

| Section | What it does |
| --- | --- |
| **Coastline Current Solutions** | Customer-facing pricing & booking app: browse the full product catalogue (~170 items with live sell pricing), build a job, request custom quotes, book a time slot. Staff mode adds a dashboard, quote builder with call-out fee + Xero/CRM push, an editable price list, and customer history. |
| **Coastline Street** | Streetwear label showcase — Collection 001 "Bloodline", Volt Division mascot series, mailing-list signup. |
| **CCS Tools** | Concept page for the Cable Retrieval & Inspection Tool with product roadmap. |

All state (cart, bookings, price overrides, staff mode) persists on-device via localStorage.

## Project layout

```
www/                  ← the app itself (plain HTML/CSS/JS — no build step)
  index.html
  css/app.css
  js/data.js          ← product catalogue, pricing (cost + markup), brand data
  js/store.js         ← state + persistence
  js/app.js           ← screens, navigation, event handling
android/              ← native Android project (generated by Capacitor, committed)
ios/                  ← native iOS project (generated by Capacitor, committed)
assets/               ← 1024px icon + 2732px splash source PNGs
resources/            ← editable SVG sources for icon/splash
capacitor.config.json ← app id: au.com.coastlinecurrentsolutions.hub
```

## Local development

```bash
npm install
npm start            # serves www/ at http://localhost:8080
```

Edit anything under `www/`, refresh the browser. When you're ready to test on-device:

```bash
npx cap sync         # copies www/ into android/ and ios/
```

## Building for the stores

### Prerequisites

- **Android:** [Android Studio](https://developer.android.com/studio) (any OS). A Google Play developer account (US$25, one-off).
- **iOS:** A Mac with [Xcode 15+](https://developer.apple.com/xcode/), plus an [Apple Developer Program](https://developer.apple.com/programs/) membership (US$99/year).

### Android (Google Play)

1. `npm install && npx cap sync android`
2. `npx cap open android` — opens the project in Android Studio.
3. Create a signing key (once): **Build → Generate Signed App Bundle → Create new keystore**. **Back the keystore up** — losing it means you can't update the app.
4. Build a release **AAB**: `Build → Generate Signed App Bundle`, choose `release`.
5. In [Google Play Console](https://play.google.com/console): create the app (name **Coastline Hub**, package `au.com.coastlinecurrentsolutions.hub`), upload the AAB under **Production → Create release**.
6. Complete the store listing (copy in `STORE_LISTING.md`), content rating questionnaire, data-safety form (see `PRIVACY_POLICY.md` — the app collects no data), and privacy policy URL (host `PRIVACY_POLICY.md` on your website, e.g. `coastlinecurrentsolutions.com.au/app-privacy`).
7. Submit for review. First review typically takes a few days.

Command-line alternative once a keystore exists:

```bash
cd android && ./gradlew bundleRelease
# output: android/app/build/outputs/bundle/release/app-release.aab
```

### iOS (App Store)

1. On a Mac: `npm install && npx cap sync ios`
2. `npx cap open ios` — opens the project in Xcode.
3. In **Signing & Capabilities**, select your Apple Developer team; Xcode manages certificates/profiles automatically.
4. Select **Any iOS Device**, then **Product → Archive**.
5. In the Organizer window, **Distribute App → App Store Connect → Upload**.
6. In [App Store Connect](https://appstoreconnect.apple.com): create the app (bundle ID `au.com.coastlinecurrentsolutions.hub`), fill in the listing (copy in `STORE_LISTING.md`), add screenshots (6.7" and 6.5" iPhone sizes required), privacy details ("Data not collected"), and the privacy policy URL.
7. Add the uploaded build to the version and **Submit for Review**.

### Updating the app later

1. Edit `www/`, bump `version` in `package.json`, and:
   - Android: bump `versionCode`/`versionName` in `android/app/build.gradle`
   - iOS: bump version/build in Xcode project settings
2. `npx cap sync`
3. Rebuild + re-upload through the same flow.

### Regenerating icons/splash

Edit `resources/icon.svg` / `resources/splash.svg`, export to `assets/icon.png` (1024×1024) and `assets/splash.png` (2732×2732), then:

```bash
npm run assets && npx cap sync
```

## Store-readiness notes

- **Guideline 4.2 (minimum functionality), Apple:** Apple rejects apps that are "just a website". This app runs fully offline, has interactive tooling (job builder, quote calculator, editable price list) and on-device persistence, which is the right side of that line. Keep adding native value (push notifications for booking updates via `@capacitor/push-notifications` is the natural next step).
- **Bookings are device-local today.** The booking flow stores jobs on the device and shows a confirmation; there is no backend yet. Before taking real bookings, wire `Store.submitBooking()` (in `www/js/store.js`) to your backend/email/SMS service so requests actually reach the office. Until then, treat store builds as a catalogue + quoting tool.
- **Xero / CRM buttons** in staff mode are visual placeholders — wire them to real integrations when ready.
- **Product images** hot-link Sparky Direct product pages and fall back to a category tile when offline or if an image disappears.
